Constraints to review

  • Target identity: claims and handoffs each reference exactly one task or plan, never both and never neither.
  • Claims: at most one active claim per target. Ended records remain in history. Store only the SHA-256 secret hash.
  • Final evidence: at most one canonical final handoff per target. Later standalone handoffs remain annotations. Final plan summaries reference canonical endings for their exact task set.
  • History: handoffs and publication receipts are append-only. Enforcing immutability through helper validation versus database triggers remains undecided.
  • Revisions: add nullable integer columns; interpret legacy NULL as zero, and assign explicit revisions to new records.
  • Retries: save operation receipts in the same transaction as changes. Identical replay returns the saved result; operation ID reuse with different content fails.
  • Migration: preserve existing IDs, sequences, fields, and history through additive upgrades.

Draft choices and remaining details

  • The FinalHandoffSources join table is a proposed representation of source references. Its composite key and validation rules need approval.
  • canonical_final and retrospective flags are draft representations of ending evidence and reconstructed historical summaries.
  • Publication metadata fields, publication identity, and duplicate-publication policy need definition.
  • Exact nullability, CHECK constraints, FK deletion rules, timestamp/UUID representations, and indexes require a full DDL review before implementation.
  • Linked-source repository/commit/blob identity and retained staged-proposal compatibility need schema decisions; the current plan fields alone do not settle their storage.
  • Structured handoff metadata needs a versioned contract for repository facts, dirty-tree snapshots, outcome, and unknowns.
